## 1. 背景（Background）

タシケントではレストラン数が増加しており、観光客・在住外国人・地元住民が「どこで食べるか」を判断する際、信頼できる口コミと多言語情報の不足が課題となっている。既存の地図アプリや SNS では、料理ジャンル・価格帯・来店体験を一元的に比較しにくい。

さらに、ウズベク語・ロシア語・英語・日本語など、利用者の母語が多様であるため、単一言語のみのサービスでは情報アクセスに格差が生じる。

---

## 2. 課題（Problem）

本プロジェクトが解決する具体的な課題は以下のとおりである。

1. **情報の分散** — レストラン情報が各媒体に散在し、評価・写真・住所を一か所で比較できない。
2. **言語の壁** — 外国人や日本語話者が、現地語のみの情報に依存せざるを得ない。
3. **信頼できる口コミの不足** — 来店日・評価・本文が揃った、再現性のあるレビューが少ない。
4. **運営管理の困難** — 店舗情報の登録・公開・モデレーションを行う統合管理手段が必要。

---

## 3. 目的（Purpose）

Taomchi は、上記課題に対し、**多言語 UI** と **ユーザー投稿型レビュー** を備えた Web アプリケーションを提供することを目的とする。

具体的には次を達成する。

- タシケントのレストランをカテゴリ・検索・フィルタで発見できるようにする。
- 認証済みユーザーが評価・本文・画像付きレビューを投稿できるようにする。
- 管理者が店舗・カテゴリ・ユーザー・レビューをひとつの管理画面で管理できるようにする。
- Vercel + Neon PostgreSQL + Vercel Blob による本番運用構成を実現する。

---

## 4. 対象ユーザー（Target users）

| ユーザー種別 | 想定ニーズ |
|--------------|-----------|
| **一般ユーザー（USER）** | レストラン検索・詳細閲覧・口コミ投稿・プロフィール管理 |
| **管理者（ADMIN）** | 店舗 CRUD・カテゴリ管理・レビューモデレーション・ユーザー管理 |
| **未ログインゲスト** | 一覧・詳細の閲覧、ログイン／登録、言語切替 |

想定ペルソナ：
- タシケント在住の大学生（ウズベク語・ロシア語）
- 出張・留学中の日本語話者（日本語 UI）
- 英語圏からの観光客・旅行者

---

## 5. 主要機能（Main features）

実装済み機能のみを記載する。未実装の地図埋め込みは含めない。

### 5.1 公開機能（ゲスト含む全ユーザー）

- **ホーム画面** — カテゴリグリッド、高評価レストラン、新着レストラン、ヒーロー検索
- **レストラン一覧** — グリッド／リスト表示、キーワード検索、カテゴリ・都市・評価・価格帯・ソートフィルタ、ロードモア
- **レストラン詳細** — ギャラリーカルーセル、情報カード（住所・電話・営業時間・価格帯）、評価ショーケース、レビュー一覧
- 4 言語対応 UI（英語・ウズベク語・ロシア語・日本語）、URL ロケールプレフィックス（`/en`, `/uz`, `/ru`, `/ja`）
- 404 ページ、エラーバウンダリ、Open Graph メタデータ

### 5.2 認証・アカウント（登録ユーザー）

- メール／パスワードによる登録・ログイン（Auth.js Credentials + bcrypt）
- プロフィール閲覧・編集（氏名、言語設定、ヘッドライン、アバター画像）
- JWT セッション、ミドルウェアおよびサーバー側ガードによる `/profile` 保護

### 5.3 レビュー機能（登録ユーザー）

- レビュー作成（評価 1〜5 点、タイトル、本文、来店日、写真最大 4 枚）
- 自分のレビューの編集・削除（ダイアログ UI）
- サーバー側権限チェックによる他ユーザーレビューへの不正操作防止

### 5.4 管理機能（ADMIN ロールのみ）

- 管理ダッシュボード（統計：店舗数・ユーザー数・レビュー数・平均評価、最近の活動）
- レストラン CRUD（多言語説明、座標、公開フラグ、メイン画像・ギャラリー）
- カテゴリ CRUD（4 言語名称、スラグ）
- レビュー一覧・編集・削除
- ユーザー一覧・ロール変更・有効化／無効化

### 5.5 画像アップロード

- 本番環境：**Vercel Blob** による CDN 配信
- 開発環境：ローカル `public/uploads/` への保存
- サーバー側バリデーション（JPEG / PNG / WebP、最大 5 MB）

> **補足：** 当初 Cloudinary を検討したが、ウズベキスタン国内でサービスが利用できなかったため、Vercel Blob に切り替えた。

### 5.6 品質・デプロイ

- Vitest 単体テスト（21 ケース全 Pass）
- Playwright E2E テスト（19 ケース定義、3 ケース自動 Pass、主要フロー手動確認済み）
- TypeScript 型チェック・ESLint・本番ビルド成功
- Vercel + Neon PostgreSQL デプロイ手順（`docs/DEPLOYMENT.md`）
